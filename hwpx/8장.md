## 8.1 시뮬레이터와 Gazebo Harmonic

### 왜 시뮬레이터인가 — 가상의 연습 비행장
비행기 조종사가 실제 비행기에 오르기 전에 비행 시뮬레이터로 수없이 연습하듯, 로봇 개발자도 실제 로봇을 움직이기 전에 시뮬레이터에서 코드를 검증합니다. 실제 로봇은 비싸고, 잘못된 코드 한 줄에 망가질 수 있으며, 실험할 때마다 배터리 충전과 공간 확보 같은 번거로운 준비가 필요합니다.

시뮬레이터는 **가상 로봇, 가상 센서, 가상 물리 환경**을 제공하면서도 실제 로봇과 동일한 ROS 2 인터페이스(토픽, 서비스, 액션)를 그대로 사용합니다. 덕분에 시뮬레이터에서 검증한 코드를 거의 수정 없이 실제 로봇에 올릴 수 있습니다.

```text
[내 코드(노드)] --/cmd_vel--> [시뮬레이터 속 가상 로봇]
[내 코드(노드)] <--/scan----- [시뮬레이터 속 가상 라이다]
```

### Gazebo Harmonic — Jazzy의 짝
ROS 2에서 가장 널리 쓰이는 시뮬레이터는 **가제보(Gazebo)** 입니다. 다만 이름이 같아도 세대가 나뉘는 점에 주의해야 합니다. 과거에 오래 쓰이던 **Gazebo Classic**(gazebo11)은 지원이 종료되었고, ROS 2 Jazzy와 짝을 이루는 버전은 신형 아키텍처로 재작성된 **Gazebo Harmonic**(구 Ignition 계열)입니다.

| 구분 | Gazebo Classic | Gazebo Harmonic |
| :--- | :--- | :--- |
| **실행 명령** | `gazebo` | `gz sim` |
| **ROS 연동 패키지** | `gazebo_ros` | `ros_gz` |
| **로봇 스폰 도구** | `spawn_entity.py` | `ros_gz_sim`의 `create` |
| **지원 상태** | 지원 종료(EOL) | ROS 2 Jazzy 공식 짝 |

표 8-1. Gazebo Classic과 Gazebo Harmonic의 비교

ROS 2와 Gazebo 사이의 연결은 **ros_gz** 패키지군이 담당하며, 그중 두 패키지가 핵심입니다.

* `ros_gz_sim` — Gazebo 시뮬레이터 실행과 로봇 생성(spawn)을 담당합니다.
* `ros_gz_bridge` — ROS 2 토픽과 Gazebo 내부 토픽을 서로 변환(bridge)해 줍니다.

### 설치와 실행 확인
`ros-jazzy-desktop`을 설치했다면 보통 포함되어 있지만, 다음 명령으로 명시적으로 설치할 수 있습니다.

```bash
sudo apt install ros-jazzy-ros-gz
```

Gazebo가 정상적으로 설치되었는지 빈 월드(world)를 띄워 확인해 봅니다.

```bash
gz sim empty.sdf
```

바닥 평면만 있는 빈 3차원 공간 창이 뜨면 정상입니다.

> **정의(1) 시뮬레이터(simulator)**  
> 실제 로봇과 동일한 ROS 2 인터페이스를 유지하면서 가상의 로봇 모델, 센서, 물리 법칙을 소프트웨어로 재현하는 프로그램이다. 코드를 실제 하드웨어에 적용하기 전에 안전하게 검증하는 용도로 쓴다.

> ⚠️ **인터넷 자료를 따라 할 때 주의**  
> 인터넷의 ROS 2 Gazebo 튜토리얼 상당수는 아직 구버전(Foxy + Gazebo Classic) 기준입니다. 자료에 `gazebo_ros`, `libgazebo_ros_*` 플러그인, `spawn_entity.py`가 보이면 Jazzy에서는 그대로 동작하지 않으므로, 이 장에서 배우는 `ros_gz` 방식으로 바꿔 읽어야 합니다.

## 8.2 URDF — 로봇을 글로 기술하기

### 링크와 조인트
시뮬레이터에 로봇을 띄우려면 먼저 "우리 로봇은 이렇게 생겼다"라고 컴퓨터가 이해할 수 있는 형식으로 알려주어야 합니다. 이 역할을 하는 것이 **URDF(Unified Robot Description Format)** 파일입니다. URDF는 로봇을 두 가지 요소의 조합으로 기술하는 XML 문서입니다.

* **링크(link)**: 로봇을 구성하는 강체 부품입니다. 몸통, 바퀴, 센서 하나하나가 링크입니다.
* **조인트(joint)**: 링크와 링크를 연결하는 관절입니다. 회전, 직선 이동, 고정 등 연결 방식을 정의합니다.

사람 몸에 비유하면 팔뚝과 손이 링크이고, 둘을 잇는 손목이 조인트입니다.

### 두 바퀴 로봇 URDF 작성하기
가장 단순한 형태의 이동 로봇을 기술해 보겠습니다. `my_robot_description/urdf/my_robot.urdf` 파일을 생성하고 아래 내용을 작성합니다.

```xml
<?xml version="1.0"?>
<robot name="my_robot">

  <!-- 본체 링크 -->
  <link name="base_link">
    <visual>
      <geometry><box size="0.4 0.2 0.1"/></geometry>
    </visual>
    <collision>
      <geometry><box size="0.4 0.2 0.1"/></geometry>
    </collision>
    <inertial>
      <mass value="2.0"/>
      <inertia ixx="0.01" ixy="0" ixz="0" iyy="0.01" iyz="0" izz="0.01"/>
    </inertial>
  </link>

  <!-- 왼쪽 바퀴 링크 -->
  <link name="left_wheel">
    <visual><geometry><cylinder radius="0.05" length="0.03"/></geometry></visual>
  </link>

  <!-- 본체와 바퀴를 잇는 회전 조인트 -->
  <joint name="left_wheel_joint" type="continuous">
    <parent link="base_link"/>
    <child link="left_wheel"/>
    <origin xyz="0 0.12 0" rpy="1.5708 0 0"/>
    <axis xyz="0 0 1"/>
  </joint>

</robot>
```

이 코드에서 반드시 이해해야 할 요소는 다음과 같습니다.

* **`<visual>` / `<collision>` / `<inertial>`**: 각각 화면에 보이는 형상, 물리 엔진의 충돌 계산용 형상, 질량·관성 정보입니다. 특히 시뮬레이터에서 물리가 동작하려면 `<inertial>`(질량·관성)이 반드시 있어야 합니다. 이 항목이 없으면 로봇이 바닥으로 꺼지거나 튀어 오르는 현상이 발생합니다.
* **조인트 타입**: `continuous`(무한 회전, 바퀴용), `revolute`(각도 제한이 있는 회전, 로봇 팔 관절용), `prismatic`(직선 이동), `fixed`(고정, 센서 장착용)가 대표적입니다. 바퀴는 끝없이 돌아야 하므로 `continuous`를 사용합니다.
* **`<origin>`의 xyz와 rpy**: 부모 링크 기준으로 자식 링크가 놓일 위치(xyz)와 회전(roll–pitch–yaw, 라디안 단위)입니다. 원기둥(cylinder)은 기본적으로 세워진 모양이므로, 바퀴처럼 옆으로 눕히기 위해 roll에 `1.5708`(= π/2, 90도)을 지정했습니다.

> **정의(2) URDF(Unified Robot Description Format)**  
> 로봇의 형상과 구조를 링크(강체)와 조인트(연결)의 조합으로 기술하는 XML 기반의 로봇 모델 표준 형식이다. 시각화, 충돌 검사, 물리 시뮬레이션에 공통으로 쓰인다.

> **[칼럼] xacro — 반복을 줄이는 매크로**  
> 왼쪽 바퀴와 오른쪽 바퀴처럼 좌우 대칭인 부품을 URDF로 일일이 쓰면 코드가 길어지고 실수하기 쉽습니다. 그래서 실무에서는 매크로 기능을 제공하는 **xacro** 형식을 널리 사용합니다. 바퀴를 매크로로 한 번 정의한 뒤 `prefix`와 `y_offset` 같은 인자만 바꿔 두 번 호출하는 방식입니다. 다만 입문 단계에서는 먼저 순수 URDF로 구조를 정확히 이해하는 것이 좋습니다.

## 8.3 RViz로 모델 확인하기

### robot_state_publisher — 모델을 TF로 알리기
물리 시뮬레이션을 돌리기 전에, 작성한 URDF 모델이 의도대로 생겼는지 시각화 도구 **RViz**로 먼저 확인하는 것이 좋은 습관입니다. 이때 핵심 역할을 하는 노드가 `robot_state_publisher`입니다. 이 노드는 URDF를 읽어 각 링크가 공간상 어디에 있는지를 좌표 변환(TF) 정보로 발행하고, RViz는 그 TF를 받아 로봇 모델을 그립니다.

`my_robot_description/launch/display.launch.py` 파일을 생성하고 작성합니다.

```python
from launch import LaunchDescription
from launch_ros.actions import Node
import os
from ament_index_python.packages import get_package_share_directory


def generate_launch_description():
    # 패키지 공유 폴더에서 URDF 파일 경로를 얻어 파일 내용을 읽음
    urdf = os.path.join(
        get_package_share_directory("my_robot_description"),
        "urdf", "my_robot.urdf")
    with open(urdf, "r") as f:
        robot_desc = f.read()

    return LaunchDescription([
        # URDF 내용을 robot_description 파라미터로 전달
        Node(package="robot_state_publisher",
             executable="robot_state_publisher",
             parameters=[{"robot_description": robot_desc}]),
        # 조인트 각도를 슬라이더로 조작하는 GUI
        Node(package="joint_state_publisher_gui",
             executable="joint_state_publisher_gui"),
        Node(package="rviz2", executable="rviz2"),
    ])
```

빌드 후 런치 파일을 실행합니다.

```bash
cd ~/ros2_ws
colcon build --packages-select my_robot_description
source install/setup.bash
ros2 launch my_robot_description display.launch.py
```

RViz 창이 뜨면 왼쪽 하단의 **Add** 버튼으로 `RobotModel` 디스플레이를 추가하고, 왼쪽 상단의 **Fixed Frame**을 `base_link`로 지정합니다. 작성한 상자 모양 본체와 바퀴가 화면에 보이면 성공입니다. `joint_state_publisher_gui`의 슬라이더를 움직이면 바퀴가 회전하는 것도 확인할 수 있습니다.

### 좌표계와 TF 프레임 기초
로봇 위치와 관련된 문제의 절반은 좌표계 문제입니다. ROS 2의 대표 좌표 규칙은 **x축이 로봇 전방, y축이 왼쪽, z축이 위쪽**입니다. 그리고 로봇 시스템에는 목적이 다른 여러 좌표 프레임이 존재합니다.

| 프레임 | 의미 | 주로 쓰는 곳 |
| :--- | :--- | :--- |
| `base_link` | 로봇 본체 중심 | URDF 작성, 센서 장착 기준 |
| `odom` | 바퀴 오도메트리 기준의 연속 좌표 | 짧은 시간의 주행 추정 |
| `map` | SLAM/위치 추정이 보정한 전역 지도 좌표 | 내비게이션 목표 좌표 |

표 8-2. 대표적인 TF 프레임과 역할

`robot_state_publisher`는 URDF에 적힌 정적 관계(예: `base_link → left_wheel`)를 발행하고, `odom → base_link`는 오도메트리가, `map → odom`은 SLAM 노드가 만듭니다. 이 `map → odom → base_link` 연결 고리는 이후 SLAM과 내비게이션을 배울 때 반드시 다시 만나게 되므로, 지금 이름과 역할을 눈에 익혀 두는 것이 좋습니다.

## 8.4 Gazebo에 스폰하고 브리지 연결하기

### 로봇 스폰하기
이제 RViz에서 확인한 로봇을 Gazebo의 물리 세계에 실제로 생성(spawn)해 보겠습니다. `my_robot_description/launch/spawn.launch.py` 파일을 작성합니다.

```python
from launch import LaunchDescription
from launch.actions import IncludeLaunchDescription
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch_ros.actions import Node
from ament_index_python.packages import get_package_share_directory
import os


def generate_launch_description():
    # 1) Gazebo Harmonic을 빈 월드로 실행
    gz_share = get_package_share_directory("ros_gz_sim")
    gz_sim = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(gz_share, "launch", "gz_sim.launch.py")),
        launch_arguments={"gz_args": "empty.sdf"}.items(),
    )
    # 2) robot_description 토픽의 URDF를 읽어 로봇을 생성
    spawn = Node(
        package="ros_gz_sim", executable="create",
        arguments=["-topic", "robot_description", "-name", "my_robot"],
        output="screen",
    )
    return LaunchDescription([gz_sim, spawn])
```

핵심은 `ros_gz_sim` 패키지의 `create` 실행 파일입니다. `-topic robot_description` 옵션은 "robot_description 토픽에 발행된 URDF를 읽어서 로봇을 만들라"는 의미이므로, 실제로는 8.3의 `robot_state_publisher`가 함께 실행되어 있어야 합니다.

### 브리지 — ROS 2와 Gazebo 잇기
Gazebo 내부의 토픽과 ROS 2의 토픽은 별개의 세계입니다. 예를 들어 ROS 2에서 속도 명령 `/cmd_vel`을 발행해도 Gazebo 속 로봇에게는 전달되지 않습니다. 두 세계를 이어주는 통역사가 `ros_gz_bridge`의 `parameter_bridge`입니다. 위 런치 파일의 `LaunchDescription`에 다음 노드를 추가합니다.

```python
    bridge = Node(
        package="ros_gz_bridge", executable="parameter_bridge",
        arguments=["/cmd_vel@geometry_msgs/msg/Twist@gz.msgs.Twist"],
    )
```

인자의 형식은 `토픽명@ROS메시지타입@Gazebo메시지타입`입니다. 이렇게 하면 ROS 2의 `geometry_msgs/msg/Twist` 메시지가 Gazebo의 `gz.msgs.Twist` 메시지로 변환되어 시뮬레이터 속 로봇에 전달됩니다.

---

> **[워크드 예제] 토픽 발행으로 시뮬레이션 로봇 움직이기**  
> 별도의 조종 프로그램 없이, 3장에서 배운 `ros2 topic pub` 명령만으로 Gazebo 속 로봇을 움직여 보겠습니다.
>
> 1단계. `spawn.launch.py`(브리지 포함)를 실행하여 Gazebo에 로봇을 띄웁니다.
> ```bash
> ros2 launch my_robot_description spawn.launch.py
> ```
> 2단계. 새 터미널에서 브리지가 만든 토픽이 보이는지 확인합니다.
> ```bash
> ros2 topic list    # /cmd_vel이 목록에 있어야 함
> ```
> 3단계. 전진 속도 0.2m/s와 회전 속도 0.3rad/s를 함께 발행합니다.
> ```bash
> ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
>   "{linear: {x: 0.2}, angular: {z: 0.3}}"
> ```
> Gazebo 화면에서 로봇이 원을 그리며 도는 것을 확인할 수 있습니다. 직진 성분과 회전 성분이 동시에 주어지면 원 궤적이 만들어집니다. `Ctrl+C`로 발행을 멈추면 로봇도 멈춥니다. 시뮬레이터 속 로봇도 실제 로봇과 완전히 동일한 `/cmd_vel` 인터페이스로 움직인다는 점이 핵심입니다.

## 코드 해설 · 실행 확인 · 버전 체크

- **코드 해설 포인트**: URDF의 링크/조인트 구조와 `<visual>`·`<collision>`·`<inertial>`의 역할 구분, `robot_state_publisher`의 TF 발행 원리, `ros_gz_sim create`의 스폰 방식, `parameter_bridge`의 `@` 매핑 규칙을 상세히 이해합니다.
- **실행 확인 포인트**: RViz에서 `RobotModel`이 표시되는지, `gz sim`으로 Gazebo가 뜨고 로봇이 스폰되는지, `/cmd_vel` 발행 시 로봇이 실제로 움직이는지 확인합니다. `ros2 topic list`에 브리지가 만든 토픽이 잡히는지도 검증합니다.
- **버전/환경 체크**: ROS 2 Jazzy + Gazebo Harmonic + `ros_gz` 조합을 기준으로 검토합니다. 구버전(Gazebo Classic + `gazebo_ros`) 방식과 혼동하지 않도록 주의합니다.

| :--- | :--- | :--- |

   * (나) 360도 회전하는 구동 바퀴의 연결부
   * (다) 상자 모양의 로봇 몸통
   * (라) 0~90도 범위에서만 움직이는 로봇 팔 관절의 연결부

## 정리

* 시뮬레이터는 가상 로봇·센서·물리 환경을 제공하면서 실제 로봇과 동일한 ROS 2 인터페이스를 사용하므로, 검증한 코드를 실기체에 거의 그대로 적용할 수 있습니다.
* ROS 2 Jazzy의 짝은 **Gazebo Harmonic**이며, ROS 2와의 연결은 `ros_gz_sim`(실행·스폰)과 `ros_gz_bridge`(토픽 변환)가 담당합니다.
* URDF는 로봇을 링크(강체)와 조인트(연결)의 조합으로 기술하는 XML 형식이며, 물리 시뮬레이션에는 `<inertial>` 정보가 반드시 필요합니다.
* `robot_state_publisher`가 URDF를 TF로 발행하면 RViz에서 모델을 확인할 수 있고, `ros_gz_sim`의 `create`로 Gazebo에 스폰한 뒤 `parameter_bridge`로 `/cmd_vel` 같은 토픽을 연결하면 ROS 2 명령으로 가상 로봇을 움직일 수 있습니다.

---

## 핵심 용어

* **Gazebo Harmonic**: ROS 2 Jazzy와 짝을 이루는 3차원 물리 시뮬레이터. 구형 Gazebo Classic을 대체한다.
* **URDF(Unified Robot Description Format)**: 로봇의 형상과 구조를 링크와 조인트로 기술하는 XML 기반 로봇 모델 형식
* **TF(transform)**: 로봇 시스템 내 여러 좌표 프레임(`map`, `odom`, `base_link` 등) 사이의 위치·회전 관계를 나타내는 좌표 변환 체계
* **스폰(spawn)**: 시뮬레이터의 가상 세계 안에 로봇 모델을 생성하여 배치하는 것
* **ros_gz_bridge**: ROS 2 토픽과 Gazebo 내부 토픽을 상호 변환하여 두 시스템의 통신을 중개하는 브리지 패키지

## 연습문제 해설(요약)

* **1번 문제**: `left_wheel` 링크와 `left_wheel_joint`를 복사하여 이름을 `right_wheel`, `right_wheel_joint`로 바꾸고, `<origin>`의 y 값을 `0.12`에서 `-0.12`로 수정합니다.
* **2번 문제**: `<visual>` 안에 `<material name="blue"><color rgba="0 0 1 1"/></material>`를 추가합니다. `rgba`의 네 값은 빨강·초록·파랑·불투명도입니다.
* **3번 문제**: `launch_arguments={"gz_args": "shapes.sdf"}.items()`처럼 다른 `.sdf` 파일명으로 바꾸면 됩니다.
* **4번 문제**: 직진은 `"{linear: {x: 0.2}}"`, 제자리 회전은 `"{angular: {z: 0.5}}"`, 원 운동은 두 성분을 함께 지정합니다. 로봇이 움직이면 브리지가 ROS 2 → Gazebo 방향으로 명령을 전달한 것입니다.
* **5번 문제**: (가) 고정 연결이므로 **조인트 — `fixed`**, (나) 무한 회전이 필요하므로 **조인트 — `continuous`**, (다) 강체 부품이므로 **링크**, (라) 회전 각도에 제한이 있으므로 **조인트 — `revolute`**.
